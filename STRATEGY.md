## Git branching strategy

**commit to main**

All work is committed directly to `main`. There are no feature branches
and no pull requests, so PR-related steps below are marked N/A.

## Manual vs automated steps

Everything not marked **Manual** is done by AI without asking.


### PHASE 1 - SPEC

- research — Automated (AI)
- spec — Automated (AI)
- spec review — Automated (AI)
- spec validation — **Manual**
- spec revision (loop until pass) — Automated (AI)
- commit — Automated (AI)
- push & pull request — N/A (not used with this workflow)

### PHASE 2 - TASKS

- tasks — Automated (AI)
- review tasks — Automated (AI)
- validate tasks — **Manual**
- task revision (loop until pass) — Automated (AI)
- commit — Automated (AI)
- push & pull request — N/A (not used with this workflow)

### PHASE 3 - IMPLEMENTATION

- write tests — Automated (AI)
- implement feature — Automated (AI)
- run tests — Automated (AI)
- fix (loop until pass) — Automated (AI)
- commit — Automated (AI)
- push & pull request — N/A (not used with this workflow)

### PHASE 4 - REVIEW

- review — Automated (AI)
- commit review — Automated (AI)
- PR validation — **Manual**
- request changes (loop until pass) — Automated (AI)
- revision (loop until pass) — Automated (AI)
- commit revision (loop until pass) — Automated (AI)
- merge pull request — N/A (not used with this workflow)

## Book

As the project progresses, a book is written taking the reader through the
project step by step with code samples — each feature is its own chapter.
The book is saved as a single Markdown file at `artifacts/books/fib-om-v2.md`,
and each pull request includes its relevant chapter.
