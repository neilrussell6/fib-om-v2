# Implementation changelog — 02-basic-crud

- Date: 20261031-215000
- Feature: 02-basic-crud
- Phase: 3 (Implementation)

## implement

**Dependencies:** `nuqs`, `@tanstack/react-table` (v9 API: `useTable`, `tableFeatures`, `createColumnHelper`), `react-hook-form`, `@hookform/resolvers`; shadcn table, alert-dialog, popover, command, dialog, select, switch, checkbox, textarea, dropdown-menu, badge (the customised button was not overwritten).

**Schema** (5 Atlas migrations, from v1's schema in `../fib-om-v2-reference/migrations/`): (AC 1–4)
- `reference_data`: clients, product_categories (36 `show_*` flags, as in v1), product_types, product_sizes, product_media, products. Identity keys `GENERATED BY DEFAULT` so spec 04 can insert legacy ids. Only the required fields are `NOT NULL`. FKs `ON DELETE RESTRICT`.
- `orders`: enums `order_status`, `docket_status`; delivery_dockets with generated `docket_number = lpad(id, 6, '0')`; orders (no unique order number).
- `order_items`: enums for clip type/position, wire mesh, 1-or-2 attributes; 7 stage booleans; no CHECK constraints on quantities or dimensions.
- `search_indexes`: `pg_trgm` and GIN trigram indexes on every searched text column.
- `display_views`: `products_v`, `orders_v`, `order_items_v`, `delivery_dockets_v`.

**Data layer**
- `lib/db/index.ts`: `query(text, params)` for allowlisted SQL; `DATE` parsed as `YYYY-MM-DD` strings.
- `lib/resources/` (client-safe): `types.ts`, `index.ts` (all ten resources: fields, columns, filters, default sorts, category flag groups), `schema.ts` (one zod schema per resource and mode, shared by form and action; empty optional fields → NULL). (AC 6, 15, 24–27, 31)
- `lib/db/queries/resources.ts`: per-resource table/view, select list (users never select `password_hash`), writable columns, sort and filter allowlists, combobox label/source. `TEXT_SEARCH_COLUMNS`. (AC 4, 13, 22)
- `lib/db/list-query.ts`: `listRecords` (allowlisted filters and sorts, LIKE-escaped contains matching, `count(*) OVER ()`, page sizes 10/25/50/100, default 25, `UnknownKeyError`). (AC 7, 8, 11, 13, 23)
- `lib/db/records.ts`, `lib/db/reference-search.ts` (≤25 options; dockets filterable by client), `lib/db/errors.ts` (SQLSTATE → messages with display names; anything else logged, "Something went wrong"). (AC 12, 19)
- `lib/db/queries/users.ts` `deleteUserChecked` (self and last-user rules, in a transaction). (AC 34)
- `lib/resources/actions.ts`: `saveRecord`, `deleteRecord` — session check, zod, rules (bcrypt hashing for users; docket sender from `FROM_CLIENT_ID` read at call time, "sender client is not configured" otherwise; an order's docket must belong to its client), write, `revalidatePath`. (AC 15, 21, 22, 28, 32, 33)
- `app/api/reference/[resource]/route.ts`: session-checked option search. (AC 12)

**UI** (`components/resource/`): data table (sortable headers with `aria-sort`, row click, Edit per row), filter bar (always-shown filters, Add filter menu, per-filter and Clear all, URL state via nuqs, debounced text), pagination, reference combobox (debounced, keyboard), resource form (react-hook-form + shared zod, validate on blur, pending "Saving…", toasts, grouped fieldsets), delete button with confirmation, print button, number input that ignores the wheel, page header. Generic list/detail/create/edit pages, with 40 thin page files under `app/(app)/`. Root layout wraps `NuqsAdapter`; the shell (header, sidebar) and toolbars are `print:hidden`; globals.css adds A4 `@page`, black print text, `.print-only`/`.screen-only`. All sidebar entries enabled. (AC 5–10, 12, 14, 16–18, 20, 29, 30)

**Tests**: unit (errors, schemas, resource config, nav), integration (schema, list engine, actions with auth/cache mocked, reference search), end-to-end (CRUD for all ten resources, lists, forms, users, combobox, axe). The spec 01 sidebar test was updated: spec 02 enables every entry.
