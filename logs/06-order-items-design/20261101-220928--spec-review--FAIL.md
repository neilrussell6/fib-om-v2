# Spec review — 06-order-items-design

- Date: 20261101-220928
- Feature: 06-order-items-design
- Phase: 1 (Spec)
- Result: FAIL

Verdict given by the author (spec validation is Manual), after going through each finding one at
a time. Every finding was accepted, some with changes. Author decisions are recorded under each.

## Verdict

Thorough, and the acceptance criteria are testable, but two blocking issues must be fixed. While
reviewing, the author also redirected several design decisions (status model, Due filter,
display name).

## Blocking

1. **Window functions in `order_items_v`.** `line_number` and `order_item_count` as
   `OVER (PARTITION BY order_id)` columns stop list filters from being pushed down, so every list
   and count query numbers the whole table.
   *Author: accept.* Compute both only in the panel's single-item query (correlated counts). Keep
   the view free of window functions.
2. **`order_id` in `saveOrderItemPanel`.** The spec didn't say whether `order_id` is editable, or
   which order's due date is updated when it changes.
   *Author: the panel is a design, not a complete field list.* The panel holds every field of the
   item form, Order included. Created and Due follow the selected order. Save updates the item
   first, then the due date of the order it now belongs to, in one transaction. The order id goes
   through the schema and FK. AC-25 is reworded.

## Non-blocking

1. **Stages after a product change.** *Accept.* `getProductStageFlags(productId)` (requires a
   session) returns the size name and the category's stage flags. Existing stage values are kept.
2. **Done stages the category hides.** *Accept.* They are listed with a "not used by this
   category" note and can be unticked. *Author note:* the design's status chips show the visual
   style only, not the wording or the set of statuses.
3. **Errors in collapsed sections.** *Accept.* The section with the error auto-expands, focus
   moves to the first error, and the section header shows an error count.
4. **Custom Due range listed twice.** *Author: ignore the design's Due control.* Created and Due
   are ordinary From/To range filters, as today. The `preset` filter kind is removed.
5. **Sidebar Suspense fallback.** *Accept.* The fallback renders the full no-cookie sidebar
   layout. An AC checks that the width doesn't change during load.
6. **Saved items leaving the current tab.** *Accept.* The toast names the new status, with a
   "View" action.
7. **Missing contrast pairs.** *Accept.* Add teal on `#eef5f6`, `#2c3438` on `#fafbfb`, and the
   status pills.

## Author decisions beyond the findings

- **Status model reversed:** use the real order status values (**New / Complete / Archived**) for
  the tabs, pills and panel chips. The chips are editable and change the order's status. The
  derived `item_status`, `deriveItemStatus` and the precedence tests are removed. The design
  colours map New → blue, Complete → green, Archived → grey.

## Questions for the author (answered)

- **Time zone:** Australia/Brisbane.
- **Display name:** add a nullable `users.name` column, editable on the Users form, falling back
  to the email.
- **Due default:** moot (no Due preset).
- **Complete means dispatched:** moot (no derived status).
