## Verdict

The checklist is well ordered and covers every design point and AC, but there is one blocking
security issue.

## Blocking

1. **`lib/order-items/panel.ts` mixes Server Actions with an unprotected query.** Marked
   `"use server"`, `getOrderItemPanel` becomes a public endpoint with no session check.
   *Accepted:* split into `panel-queries.ts` (`server-only`, `getOrderItemPanel`) and
   `panel-actions.ts` (`"use server"`, both actions call `requireSession()`). The AC-27 test
   asserts `panel-queries.ts` has no `"use server"`.

## Non-blocking

1. **`due_in_days` test method:** `SET LOCAL` can't override `now()`. *Accepted:* use only the JS
   comparison (`Intl`, `APP_TIME_ZONE`), with orders due today, −2 and +10, and one retry if the
   date changed during the run.
2. **Panel outside the current tab untested.** *Accepted:* an e2e step opens
   `?status=archived&item=<New item>`. The panel opens and no row is selected.
3. **`statusTabs` missing from the type.** *Accepted:* add `list.statusTabs?: boolean` to
   `ResourceUi` and set it on order items. A config test asserts only order items have it.
