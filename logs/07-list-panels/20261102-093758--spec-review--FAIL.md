# Spec review — 07-list-panels

- Date: 20261102-093758
- Feature: 07-list-panels
- Phase: 1 (Spec)
- Result: FAIL

Verdict given by the author (spec validation is Manual). Findings were walked one at a time; the
author accepted every proposed fix. The four Summary decisions (Current pill = New blue, no
Delete in panels, Orders panel = form fields only, `?item=` everywhere) were not changed.

## Verdict

FAIL. Two blocking gaps: the list goes stale after a save that closes by `router.back()`, and the
panel heading / identifying link is undefined or wrong for Products and Users.

## Blocking

1. **Stale list after Save with fix 2.** `closePanel` uses `router.back()` for list-opened panels;
   back restores the cached list from before the save, so the row can show the old value
   (breaks AC-7 and spec 06 AC-19). *Accepted fix:* after a successful Save, go back and then
   `router.refresh()`; Cancel/×/Escape don't refresh; AC-17 checks the row shows the saved value.
2. **Heading and identifying link not defined per resource.** "First column that doesn't link
   elsewhere" gives Category on Products (heading would be the category, not the product name)
   and an empty Name on Users with no name (empty, unreachable link; AC-1 fails). *Accepted fix:*
   `ResourceUi.titleField` per resource (orders `order_number`, dockets `docket_number`, products
   and lookups/clients `name`, users `name` falling back to email); the link sits on that column;
   AC-1/AC-6 list expected headings; AC-12 checks a nameless user's link shows the email.

## Non-blocking

1. **Leftover history marker.** The `panel-opened` marker is only cleared on close; navigating
   away with a panel open and later loading the same URL directly would make close go back out
   of the app. *Accepted fix:* clear it on unmount without close; AC-17 check.
2. **How the cross-client docket refusal shows.** *Accepted fix:* AC-8 names the error toast
   "Could not edit Order: delivery docket belongs to another client", panel stays open, nothing
   written; every panel uses "Could not edit <Singular>: <message>".
3. **Saving your own password signs you out.** *Accepted fix:* state it as expected (same as the
   edit page); AC-12's password test uses a user other than the signed-in one.
4. **Tab/filter change with a panel open.** *Accepted fix:* changing tab, filter, sort or page
   keeps the panel and its unsaved edits; a later close replaces; AC-14 check.
